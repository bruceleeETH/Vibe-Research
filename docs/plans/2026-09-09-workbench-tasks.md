# 日常待办与复查中心

## 范围与设计
用户确认后继续本地开发。采用读取现有记录、实时推导待办的方案；不另存任务状态，不提供掩盖源问题的完成勾选，不保留旧版本。

四类待办：
- 到期计划：未撤销且复查日期不晚于北京时间今天；区分逾期与今天到期，草稿亦显示。
- 待核验证据：未撤销卡片中状态为未核验的证据，按卡片汇总条数。
- 待关联成交：周期含缺失关联或关联不一致；明确选择无事前计划/仅记账视为已处理。
- 待复盘周期：已清仓且尚无复盘，历史不完整亦可复盘但标注不计入收益统计。

页面提供分类数量、搜索、刷新、空状态和失败重试。列表按到期日期、证券代码等稳定排序。点击处理通过记录 ID 定位；记录不存在显示明确提示。处理后返回中心重新读取，页面重新聚焦及北京时间跨日时刷新。

## 实施
1. 后端使用同一工作台快照生成待办和周期，保持只读。
2. 新增日常待办页面与统一工作台导航。
3. 卡片、证据与成交页支持直接定位及返回待办，保留未保存保护。
4. 测试日期边界、撤销排除、显式无计划、部分关联、复盘后消失、只读不写文件；浏览器验证跳转与处理闭环。

## 验收结果
- 49 项后端回归测试通过；前端 TypeScript/生产构建通过，仍有原有包体积提示。
- 浏览器使用 /tmp/bruce-tasks-qa 隔离数据验证：四类待办逐项处理，从 4 → 3 → 2 → 1 → 0，返回中心自动读取。
- 同代码两张卡片准确定位到目标卡；证据自动展开，计划日期和成交关联/复盘区域获得焦点。
- 现有本地服务 /investment-workbench/tasks 页面只读验证通过。
