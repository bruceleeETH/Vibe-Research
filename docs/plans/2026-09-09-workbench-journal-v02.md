# 投资工作台 v0.2：成交关联与复盘

状态：2026-09-09 已实现，代码尚未提交/推送。

## 使用入口

投资工作台 → 成交与复盘，地址 `/investment-workbench/journal`。

1. 自动读取现有 `trades.json`，按同一证券的建仓至归零组织周期。
2. 已有成交无需再次录入。补录实际成交要先核对方向、日期、数量和价格，再确认写入；调用现有 TradeService 同步持仓、台账、复盘基线及快照，不调用券商。
3. 选择周期，关联同证券投资卡；也可明确标记无事前计划/仅记账。关联本身不增减持仓。新增成交后提示重新关联。
4. 清仓后选择执行情况、E01–E10 错误标签及一个主要错误，填写复盘结论与下次改进动作。
5. 盈亏与执行情况分别显示，例如“盈利 · 偏离计划”。执行评价来自本人复盘，不由收益推断。

## 数据与边界

- 默认本地单账户；真实/模拟应使用独立 VR_DATA_DIR。
- 成交事实仍由原有 `trades.json`、持仓与私有台账保存。工作台 `current.json` 仅新增成交关联和周期复盘，修改覆盖旧内容。
- 不保留计划历史，因此关联当前投资卡不能证明成交前已有相同计划。
- 收益明确为未计费用的已实现毛收益；没有完整建仓记录、数量不连续、时间顺序异常的周期不计入完整周期统计。
- 现有持仓缺少成交历史时明确提醒，不能把期初持仓再次录成买入。
- 工作台成交补录只接受不早于该证券最新已记成交的日期；同日以记账顺序呈现，不推断缺失的盘中时间。
- 卖出从持仓锁内读取当前成本；无持仓、超量卖出或无效成本拒绝记账。记录成功后重试同一个交易 ID 不重复更新持仓。
- 备份恢复包含投资卡、关联和复盘，不包含源成交文件；更换机器时源成交/持仓应按既有备份机制另外保存。
- 已关联成交的卡片不能直接删除或改证券代码，需先解除关联。

## 修改位置

- `backend/workbench_journal.py`：成交周期读取、关联、复盘和补录 API。
- `backend/workbench.py`：关联与复盘持久化、备份恢复和引用约束。
- `backend/trade_service.py`：锁内自动读取卖出成本、可选日期顺序保护；既有显式成本调用仍可用。
- `frontend/src/features/workbench/TradeJournal.tsx`：实际成交核对、周期、关联、错误标签复盘。
- `frontend/src/pages/InvestmentJournalPage.tsx`、路由及工作台入口。
