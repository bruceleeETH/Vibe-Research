# 工作台手动同步简报

用户要求在工作台直接操作早晚简报同步。采用本机 Codex CLI 的 `queue --thread --message` 向现有同步任务提交固定指令，继续使用已验证的 read_thread → sync_briefs.py 归档链路。仅刷新本地内容不能满足请求；复制指令需额外手动发送，因此优先验证直接投递。

页面增加“同步早晚简报”，保留“刷新归档”。点击同步立即返回排队状态，运行中禁用重复提交；轮询展示等待执行、同步中、完成、失败或超时。完成必须由执行方确认两档来源均已检查，不以 CLI 投递成功冒充同步成功。本期未产出明确显示，不算读取失败。

目标任务从本地既有自动化配置解析，不硬编码私人任务 ID，不允许网页指定命令、路径或目标任务。POST 限制本机来源和自定义请求头，继续继承已有 API 鉴权。固定提示词不包含简报正文、持仓或成交数据，不生成简报、不修改定时计划。

请求状态保存在现有私有归档的独立字段，沿用文件锁与原子写入。执行方通过 start-manual / finish-manual 确认请求生命周期；过期、重复点击、后端重启及晚到的旧请求不会静默重复创建同步。失败保留已有正文。

验证：独立测试配置缺失、重复请求、投递失败、超时、旧请求、未检查不能完成、两档成功和来源失败；运行现有简报回归及前端构建；实际页面点击确认投递并真实读取两档，最终状态与归档一致。
