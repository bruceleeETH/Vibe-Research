# 每日交易复盘工作流（第一阶段）

## 目标

把交易日反复出现的盘前、竞价、午盘和盘后复盘变成固定流程，减少每次重新说明口径的成本，同时避免长对话压缩后混入旧持仓、旧行情或过期资讯。

第一阶段只解决三个问题：保存代码级复盘清单、生成按日期归档、为四个阶段生成一致的检查清单与提示词。它不自动交易、不定时联网，也不替代 App 中带数量和成本的账户持仓。

## 方案选择

采用“仓库保存规则，用户目录保存私人状态”的方案：

- 公共仓库保存 `backend/daily_review.py`、命令行入口、测试和说明。
- 当前持仓、清仓名单及每日复盘保存在 `~/.vibe-research/daily-review/`；可用 `VR_DATA_DIR` 或 `--root` 改位置。
- 每日 JSON 是机器可读的权威记录，Markdown 是便于人和 AI 阅读的派生文件。
- 创建某日文件时冻结当日持仓快照；以后调整当前持仓不会篡改历史复盘。

不复用 `portfolio.json`，因为它要求数量和成本，而本工作流只需要代码和名称。也不把当前11项持仓写进仓库，避免私人组合进入 Git 历史。

## 数据流与错误处理

1. `set-holdings` 原子更新代码级基线，并保证当前持仓和清仓名单互斥。
2. `prepare` 为指定日期创建四阶段空白档案；重复执行不会覆盖已有内容。
3. `prompt` 输出该阶段固定检查项、当前快照和数据纪律。
4. `record` 写入结论、数据截至时间和数据源状态，并同步生成 Markdown。

数据源状态必须是 `fresh`、`partial`、`stale`、`failed` 或 `not_checked`。资讯雷达失败时不得伪装成最新数据；实时行情必须重新获取并标注时间。向第三方行情服务发送私人持仓代码前仍需明确授权，且只发送代码，不发送数量和成本。

## 验证标准

- 无效代码、阶段、日期或数据源状态会被拒绝。
- 重复代码去重；同时出现在当前和清仓列表的代码以当前持仓为准。
- 每日快照具有历史稳定性。
- 写入任一阶段后，JSON 与 Markdown 内容一致。
- 全部测试离线运行，不访问行情或新闻服务。
