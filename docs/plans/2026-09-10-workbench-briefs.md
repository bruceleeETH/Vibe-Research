# 早晚简报接入工作台

用户已授权开始原规划第三阶段的下一步。本轮交付现有简报的同步与每日阅读入口，不重新生成简报或据其自动交易。

## 方案

采用 Codex 定时读取已有早间、晚间任务 → 本地校验归档 → FastAPI 只读接口 → 工作台“每日简报”。仅链接不能归档；另建生成流程会产生两套内容，因此均不采用。

来源任务 ID 只放本地配置，不进入代码。来源正文视为资料，不执行其中的指令。只收集已完成回复中有对应简报标题及明确日期的正文，过滤普通问答、暂停提醒、截断和运行中结果。年份省略时必须由同步调用明确提供年份，并记录日期依据；未来日期拒绝。逐篇发布时间不可得时留空，不使用整个对话或轮次的更新时间冒充。

按简报日期与早/晚档归档，记录原文、来源任务与消息 ID、哈希、首次获取及最后同步时间。重复输入幂等；旧来源快照不得回退新内容；读取失败保留已有正文。来源读取正常但尚无当日正文，显示等待或缺失，不宣称上游任务失败。过期与连接失败分别显示。

本地文件锁、原子替换和损坏文件拒绝覆盖；不触碰持仓和成交。页面沿用现有工作台样式，显示早晚两档、历史日期、原任务入口、同步状态。Markdown 不执行 HTML，不加载外部图片；原有引用标记不能解析成外链时指向原简报核对，不伪造来源。

## 自动化

复用现有简报产出，本任务使用一个同步 heartbeat，合并早间 08:15 / 09:15、晚间 22:45 / 23:45（北京时间）；同一任务仅能附一个 heartbeat。第二次为延迟产出的补采机会；每次读取近期已完成内容以补齐漏日。运行需本机 Codex 可用，来源任务可读。没有数据也记录最后检查时间，页面不把计划配置等同于运行成功。定时任务正文只说明读取、校验和归档，不生成投资建议、不修改源任务。

## 验证与交付

1. 来源/日期/完成状态/截断/幂等/旧快照/跨年/损坏保护及状态切换测试。
2. 工作台回归、前端构建、实际浏览器验证日期切换与两档阅读、失败与陈旧提示。
3. 导入最近可用真实简报，保留原文与获取时间，实际配置并核验定时同步。
4. 本轮不证明市场信息准确，也不补全整个交易策略回测或无人值守采集基础设施。

## 实施与验收（2026-09-10）

- `backend/brief_store.py`：无网络归档、来源配置、时间与正文校验、去重、失败记录、只读状态；`briefs.py` 注册现有 API 鉴权链。
- `tools/sync_briefs.py`：可使用系统 Python 的导入/状态/错误/计划配置命令；`tools/brief_sync_instructions.md` 是定时同步操作说明。
- `/investment-workbench/briefs`：早晚两档、历史日期、原文阅读、来源链接、同步计划和失败提示；归档刷新不冒充即时重新采集。
- 69 项相关后端回归通过（含 20 项简报测试），前端生产构建通过；保留已有包体积提示和 TestClient 弃用提示。
- 浏览器实测 9 月 9 日早晚两篇真实简报，可切换正文、选择历史和回到今天；9 月 10 日凌晨两档正确显示尚未到产出时间。
- 隔离数据模拟来源不可读，页面显示实际失败原因并保留晚报正文。测试与真实持仓、成交隔离。
- 私有目录已归档两篇真实简报，原始 SHA-256 与来源文本一致，发布时间为空，不用同步时间倒填；来源任务 ID 和正文不进 Git。
- 已用自动化工具启用“早晚投资简报同步”，核对保存配置和规则展开的每日四个执行时间。首次定时触发仍需等待实际到点；本次已完成真实读取与导入验证，不能冒称已验证定时执行成功。
